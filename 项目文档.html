1 项目概述

项目名称

AI 技能编排系统 (springboot-ai-skill)

技术栈

SpringBoot 2.7.18 JDK 8 FTP 存储 (commons-net) OpenAI 兼容 API 原生 HTML/CSS/JS 前端 SnakeYAML commons-compress

核心功能

功能 说明
技能上传 支持上传 skill.md 及附件文件，或上传压缩包（.zip / .tar.gz / .tar）自动解压校验。文件通过 FTP 持久化存储。
技能管理 列出所有技能、查看技能详情、递归浏览技能目录下全部文件、在线读取文件内容（文本文件直接显示，二进制文件返回 Base64）、删除技能。
AI自动选择技能 用户输入需求描述，系统通过 AI 语义匹配自动选择最佳技能执行，无需手动搜索。AI 不可用时回退到关键词搜索。
技能执行 支持文本输入和文件上传执行。构建 Prompt 模板（替换 {input} / {materials} / {scripts} 占位符），调用 OpenAI 兼容 API 获取结果。
多轮编排 支持技能链式编排：第一轮执行后可继续下一轮（使用上一轮输出作为输入）、返回上一轮、重新执行当前轮。每轮可使用不同技能。
技能搜索 AI 语义匹配 + 关键词搜索双模式。关键词搜索支持中英文双语映射（50+ 词条）、CJK 字符匹配、多维度评分排序。
架构特点

系统采用存储抽象层设计（StorageService 接口），当前实现为 FTP 存储。技能元数据以 meta.json 缓存在 FTP 和内存中（ConcurrentHashMap）。执行会话存储在内存中，支持多轮操作和分支回溯。

@Bean
public RestTemplate restTemplate() {
    SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
    factory.setConnectTimeout(timeout != null ? timeout : 30000);
    factory.setReadTimeout(timeout != null ? timeout : 60000);
    return new RestTemplate(factory);

核心方法
方法说明

reasoning_content 回退解析

部分推理模型（GLM、Qwen3）在 think 模式下可能将输出放在 reasoning_content 或 reasoning 字段而非 content。解析顺序：

// 1. 优先读取 content
String content = choices.get(0).path("message").path("content").asText("");
// 2. content 为空时回退到 reasoning_content
if (content == null || content.trim().isEmpty()) {
    content = choices.get(0).path("message").path("reasoning_content").asText("");
}
// 3. 仍为空时回退到 reasoning
if (content == null || content.trim().isEmpty()) {
    content = choices.get(0).path("message").path("reasoning").asText("");
}
技能语义搜索提示词

构建技能列表提示词（ID/名称/描述/标签），要求 AI 按匹配度排序返回技能ID列表，温度设为 0.3 以获得稳定结果。

src/main/java/com/example/aiskill/storage/FtpStorageService.java 后端

FTP 存储实现，实现 StorageService 接口。每次操作创建短连接（connect/disconnect），支持递归目录创建/删除/文件列表。使用 @PostConstruct 在 Bean 初始化时连接 FTP 并创建根目录。

连接配置
  • 被动模式 (enterLocalPassiveMode())
  • 二进制文件类型 (FTP.BINARY_FILE_TYPE)
  • 控制连接保活超时 60 秒 (setControlKeepAliveTimeout(60))
关键特性
  • 短连接模式：每次操作独立连接，避免连接断开问题
  • 递归目录创建：makeDirs() 类似 mkdir -p
  • 递归删除：deleteDirectoryRecursive() 深度优先删除目录树
  • 递归文件列表：listFilesRecursive() 返回所有嵌套文件
  • 路径规范化：normalizeDir() 和 normalizeRelative() 确保跨平台兼容
注意

此类不使用 @Component 注解，而是由 StorageConfig 手动创建 Bean。

src/main/java/com/example/aiskill/storage/StorageConfig.java 后端

存储配置类，通过 @Value 读取 storage.ftp.* 配置，创建 FtpStorageService Bean。

5 执行流程文档

5.1 技能上传流程

步骤 1用户在前端选择文件（支持拖拽到上传区域或点击选择）
步骤 2前端检查是否包含 skill.md 或压缩包文件（.zip / .tar.gz / .tar）
步骤 3前端发送 POST /api/skills/upload（multipart/form-data），将所有文件作为 files 参数上传
步骤 4SkillService.uploadSkill() 判断上传的文件中是否包含压缩包（isArchive() 方法检查文件扩展名）
步骤 5压缩包路径：uploadSkillFromArchive() 解压到临时目录 → 递归收集文件（过滤 macOS 元数据） → 查找 skill.md → 验证名称字段
步骤 6散文件路径：uploadSkillFromLooseFiles() 直接查找 skill.md → 验证存在性
步骤 7调用 parseSkillMd() 解析 skill.md 的 YAML front matter，提取 name、description、tags、input_type、output_type、model、temperature、max_tokens 等元数据，正文部分作为 promptTemplate
步骤 8生成技能ID（skill_时间戳），创建 FTP 目录结构（skillId/、skillId/materials/、skillId/scripts/），通过 StorageService.store() 将文件持久化到 FTP
步骤 9调用 saveSkillMeta() 将 Skill 对象序列化为 meta.json 存储到 FTP
步骤 10更新内存缓存 skillCache（ConcurrentHashMap），返回技能信息
步骤 11前端收到成功响应，显示 Toast 提示，刷新技能列表，自动切换到「技能管理」Tab

5.2 技能搜索流程

步骤 1用户在技能管理 Tab 的搜索框输入描述文本，可选择开启/关闭 AI 搜索
步骤 2前端发送 POST /api/skills/search，Body: { "description": "用户输入", "useAi": true }
步骤 3SkillService.searchSkills() 获取所有技能列表，若为空直接返回空列表
步骤 4AI 语义匹配（useAi=true 且 AI 已配置）：构建技能列表提示词（ID/名称/描述/标签） → AiService.chat() 调用 AI API（温度 0.3） → 解析返回的技能ID列表（按行分割、去除前缀符号）
步骤 5若 AI 匹配返回非空结果，按 AI 返回顺序从缓存中获取 Skill 对象并返回；若 AI 调用失败或返回空，回退到关键词搜索
步骤 6关键词搜索 keywordSearch()：
• 英文单词提取（正则 [a-z]{2,}）
• 中英文双语映射（50+ 词条，如「翻译」→translate/translation）
• CJK 字符提取（Unicode 范围 \u4e00-\u9fff）
• 多维度评分：名称匹配(+3) / 描述匹配(+2) / 标签匹配(+2) / 中文名称部分匹配(+3) / 中英映射匹配(+4) / CJK匹配(+1)
步骤 7过滤评分 > 0 的技能，按评分降序排列，返回排序后的技能列表
步骤 8前端渲染搜索结果为技能卡片列表

5.3 AI自动选择执行流程

步骤 1用户在技能执行 Tab 选择「AI自动选择」模式，输入需求描述文本和可选的上传文件
步骤 2前端根据是否有文件分别调用：
• 有文件：POST /api/sessions/auto-execute-with-files（multipart）
• 无文件：POST /api/sessions/auto-execute（JSON Body）
步骤 3后端 buildInputWithFiles() 将文本输入和上传文件内容拼接（文件内容超过 50000 字符自动截断）
步骤 4SkillService.autoSelectSkill() 调用 AI 语义匹配选择最佳技能。AI 不可用时回退到关键词搜索取第一个结果
步骤 5若未找到匹配技能，返回 404 错误提示
步骤 6ExecutionService.startSession() 创建新会话（生成 sessionId），调用 executeSkillInternal() 执行第一轮
步骤 7executeSkillInternal() 调用 buildPrompt() 构建 Prompt：读取技能的材料文件和脚本文件内容，替换 {input} / {materials} / {scripts} 占位符
步骤 8AiService.chat() 调用 OpenAI 兼容 API 的 /chat/completions 接口，发送 system prompt + user message，获取 AI 响应（支持 reasoning_content 回退）
步骤 9返回会话信息，额外包含 autoSelectedSkill: true、selectedSkillName、selectedSkillId、selectedSkillDescription
步骤 10前端显示 AI 选择的技能名称和执行结果，调用 detectOutputFiles() 检测输出中的文件类型（HTML/JSON/CSV/代码块/Markdown 等），渲染文件列表支持下载和复制

5.4 技能执行流程

步骤 1用户在技能执行 Tab 手动选择技能，输入描述文本和可选的上传文件
步骤 2前端根据是否有文件分别调用：
• 有文件：POST /api/sessions/with-files（multipart: skillId, input, files[]）
• 无文件：POST /api/sessions（JSON Body: skillId, input）
步骤 3后端 buildInputWithFiles() 拼接文本输入和文件内容
步骤 4ExecutionService.startSession() 创建新会话（session_UUID前8位），初始化 rounds 列表和 currentRound=0
步骤 5executeSkillInternal() 构建状态为 "running" 的 ExecutionRound，调用 buildPrompt() 构建 Prompt 模板
步骤 6AiService.chat() 使用技能的 model/temperature/maxTokens（若配置）调用 AI API，获取输出
步骤 7设置 round 的 output 和 status="success"，将 round 添加到 session.rounds，currentRound 设为 1，返回会话信息
步骤 8前端渲染执行结果，调用 detectOutputFiles() 检测输出中的文件类型
步骤 9渲染文件列表，每种文件类型提供对应的操作：HTML 预览、JSON 格式化、CSV 表格、代码块复制、Markdown 渲染等，支持下载和复制

5.5 多轮编排流程

步骤 1第一轮执行完成后，前端显示多轮控制按钮：继续下一轮、返回上一轮、重新执行（根据 canGoBack 和 canContinue 状态控制按钮可用性）
步骤 2继续下一轮：用户选择新技能（可不同于前一轮），输入可选内容。调用 POST /api/sessions/{id}/continue-with-files（有文件）或 POST /api/sessions/{id}/continue（无文件）
步骤 3后端 continueToNext()：若 input 为空，自动使用上一轮输出作为输入（continuedFromPrevious=true）；截断当前轮之后的轮次（分支机制），执行新轮次
步骤 4返回上一轮：调用 POST /api/sessions/{id}/back。goBack() 移除当前轮次，currentRound 减 1
步骤 5重新执行：调用 POST /api/sessions/{id}/reexecute。reExecute() 使用当前轮次的技能和输入（或新输入）重新执行，替换原轮次结果
步骤 6每轮执行可使用不同技能，实现技能链式编排。例如：第一轮用「翻译技能」翻译文本 → 第二轮用「摘要技能」对翻译结果进行摘要 → 第三轮用「报告生成技能」生成报告
分支机制

当用户在第 N 轮继续执行后，又在第 N 轮再次继续（即回退后重新分支），系统会截断 N 轮之后的所有轮次，创建新的执行分支。这确保了执行历史的线性一致性。

5.6 技能文件查看流程

步骤 1用户在技能管理 Tab 点击技能卡片
步骤 2前端调用 GET /api/skills/{id} 获取技能详情（包含名称、描述、标签、文件列表等）
步骤 3前端调用 GET /api/skills/{id}/files/list 列出技能目录下的全部文件（递归遍历，包含子目录文件）
步骤 4前端渲染文件列表（显示文件名、路径、大小、是否二进制），用户点击文件名
步骤 5前端调用 GET /api/skills/{id}/files/content?path=xxx 读取文件内容
步骤 6后端 SkillService.readSkillFile() 通过 StorageService.read() 从 FTP 读取文件字节。控制器通过 isBinaryFile() 判断：文本文件返回 UTF-8 字符串，二进制文件返回 Base64 编码
步骤 7前端显示文件内容：文本文件直接显示（代码文件有语法高亮样式），二进制文件显示提示信息

5.7 应用启动流程

步骤 1AiSkillApplication.main() 调用 SpringApplication.run() 启动 Spring Boot
步骤 2Spring 容器初始化，加载 AiConfig（@ConfigurationProperties(prefix="ai") 绑定配置），创建 RestTemplate Bean
步骤 3加载 StorageConfig，读取 storage.ftp.* 配置，创建 FtpStorageService Bean
步骤 4FtpStorageService.init()（@PostConstruct）连接 FTP 服务器，创建根目录（makeDirs），输出日志 "FTP storage initialized"
步骤 5SkillService.init()（@PostConstruct）调用 storage.listDirectories("") 列出所有技能目录
步骤 6对每个技能目录调用 loadSkillFromStorage()：优先读取 meta.json（Jackson 反序列化），若损坏或不存在则回退解析 skill.md 并扫描目录文件
步骤 7将加载的技能存入 skillCache（ConcurrentHashMap），输出 "Loaded N skills from storage"
步骤 8服务就绪，监听 8080 端口，前端页面可通过 http://localhost:8080 访问

├── materials/                        # 材料文件目录
│   ├── glossary.txt                   # 术语表
│   ├── reference.md                   # 参考资料
│   └── data.csv                       # 数据文件
└── scripts/                          # 脚本文件目录
    ├── preprocess.py                  # 预处理脚本
    └── postprocess.sh                 # 后处理脚本
文件分类规则

上传时根据文件扩展名自动分类：脚本（.py, .sh, .js, .rb, .pl, .go, .java, .bat）存入 scripts/ 目录；材料（.txt, .md, .pdf, .docx, .doc, .csv, .json, .xml, .html, .yaml, .yml）存入 materials/ 目录；其他文件存入 materials/ 目录（按材料处理）。

8 部署说明

本地运行

前置条件
  • JDK 8（SpringBoot 2.7 不兼容 Java 26+）
  • Maven 3.6+
  • FTP 服务器（默认 localhost:21，用户名 admin / 密码 admin）

方式一：使用启动脚本

# 赋予执行权限
chmod +x run.sh

# 启动应用
./run.sh

run.sh 会自动查找 Java 8 环境，设置 JAVA_HOME，然后执行 mvn spring-boot:run。

方式二：手动 Maven 启动

# 确保使用 Java 8
export JAVA_HOME=/path/to/jdk8

# 编译并启动
mvn spring-boot:run

方式三：打包后运行

# 打包
mvn clean package -DskipTests

# 运行 JAR
java -jar target/ai-skill-1.0.0.jar

启动成功后，应用监听 http://localhost:8080，前端页面直接访问该地址即可。

Docker 部署

步骤 1：准备环境变量

# 复制环境变量示例文件
cp .env.example .env

# 编辑 .env，填入实际的 FTP 和 AI 配置
vim .env

步骤 2：启动服务

# 构建并启动
docker-compose up -d

# 查看日志
docker-compose logs -f backend

步骤 3：验证服务

# 检查服务状态
curl http://localhost:8080/api/skills/ai-status

# 预期返回
{"code":200,"message":"success","data":{"configured":true}}
Docker 部署注意事项
  • FTP 服务器需要独立部署，Docker Compose 中不包含 FTP 服务
  • 如果 FTP 在宿主机，FTP_HOST 应设为 host.docker.internal（Docker Desktop）或宿主机 IP
  • JVM 内存参数默认 -Xms256m -Xmx512m，可在 Dockerfile.backend 中调整
  • 容器重启策略为 unless-stopped

当使用 Ollama 运行推理模型（如 Qwen3）时，设置 ai.think: true 可启用推理模式。系统支持从 content、reasoning_content、reasoning 三个字段依次回退解析 AI 输出。
